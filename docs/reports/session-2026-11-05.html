What you can do now

  • Say or type it. The / field (at the pointer) takes plain requests: instant phrases (“create a red circle”, “three circles in a row”, “make it bigger”, “a diagonal line”), then commands, then a small model. The mic is on the / bar, the palette, the chat and Generate; it stops on a pause and sends when the request looks complete.
  • Hear it. The speaker button beside the mic makes replies spoken (LFM3-Omni's voice; 19 languages, female or male, in Settings › Model › Voice). Narration can use the same voice and turns Narration clips into audio tracks.
  • Watch it. /agent <what to do> acts a request out with the Guide cursor and captions.
  • Write code with the right model. Settings › Code model picks a bigger model for programs; write code for a spiral of 200 points uses it.
  • No Ollama (students). /browser light or /browser standard (or Settings › Browser only) runs everything in the page: LFM3-Omni for conversation and drawing, a small coder for code. Downloads once, then offline.
  • One Assistant panel with Chat | Generate | Decide modes (replaces three tabs). The Docs tab is a question mark after Shortcuts.
  • Smaller: real waveforms on audio clips, lecture recording (stage + mic + camera bubble), the mic as a Source, a request log (ams_requests), the model menu with stars, Settings controls to load, test and hear LFM3, chat that hides tool traces (details on request).

Recommendations. Ollama or LM Studio users: Qwen3-Coder 30B or Flint (fast and perfect), or the 9B coder if memory is tight. Students in the browser: Qwen3 4B Instruct 2507 (2.1 GB), or Qwen2.5-Coder 1.5B (about 1 GB) on a light laptop; LFM3-Omni for conversation and voice either way.

Things I got wrong, and fixed

  • Speeds. I first measured while a browser model was using the same GPU: numbers were 5 to 8 times too low (the Bonsai 27B read as 5 tok/s; it is 41). The docs carry the correction.
  • More examples hurt. Putting similar lesson boards in the prompt made the small model copy them (6/14 against 8/14). It is an option, off by default.
  • LFM3's own tool calling was worse than JSON with the brackets repaired (it wrote tool names as text). Off by default.
  • An unreadable reply could show as raw JSON in the chat (your screenshot). It cannot now: the sentence is salvaged, else a plain notice.
  • A model-menu bug (“not installed” on models you have), a settings bug (a saved 0.4 temperature that was only a default), and a stale-library bug in the dev server are fixed.

  • At about 2B, Qwen2.5-Coder 1.5B (10) is still the best code writer in the browser; the LFM models are not better at code. Keep LFM3-Omni for voice and tools, and route code writing through the Code model.
  • Liquid's own LFM3-1.7B ONNX needs a newer transformers.js (logits_to_keep). The Omni and Audio ONNX builds need architectures that even 4.4.0-next.0 lacks; Omni runs through Liquid's own runtime.
  • The danyalmalik builds (Qwen3-8B, Nemotron Bolt, DeepSeek R1 7B, Flint) use the Quick Inference layout and do not load in our engine; presets removed. They would need that runtime as a second engine.
  • Not done: Bonsai browser builds (the 4B Vision load error is undiagnosed) and the LFM3 tooling experiments.

Needs a decision from you

  • Make the browser tier the default for students? It is one click now (/browser); a first-run prompt when Ollama is missing is a small step.
  • Bonsai in the browser. 4B in 1.15 GB at 12/14 is the best size for students. It needs either Prism ML to publish the runtime or us to port the kernels (the demo's licence is not stated).
  • Which Code model to recommend in the docs for Ollama users: the 30B MoE (fast, 18 GB) or the 9B coder (6.7 GB).

Not checked, or limits

  • I cannot hear: voice quality and the spoken replies were produced and played, not judged.
  • Dictation was tested end to end with the real microphone, but only on room noise (nobody spoke), so recognition of real speech is untested.
  • Screen recording of a lecture (the share picker) needs a person; the camera bubble was checked with a stand-in stream.
  • The Claude app's built-in browser pane blocks the microphone; use Chrome or ego lite.
  • LFM3-VL 2B (2/14) is not a code writer; it may suit looking at pictures instead.
