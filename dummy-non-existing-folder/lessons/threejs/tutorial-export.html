Making one file you can double-click

At the end of a lesson you have a page that works on your computer. This tutorial is about handing it to someone else as one file that opens by double-click: no server, no install, no folder of other files.

1 · Why it is not already one file

A lesson looks like one page but it is really dozens of files: the HTML, the stylesheet, the page's code, the shared code in lib/, three.js, and for the body lessons several large model files. The page asks for them one by one while it loads.

When you open an HTML file straight from your disk, the address starts with file://. Browsers are strict about that: a page opened this way is not allowed to fetch other files. (Otherwise any web page you downloaded could read your whole disk.) That is why the lessons ask you to run a small server: http://localhost is allowed to fetch.

The fix: put everything the page needs inside the one HTML file. Then there is nothing to fetch.

2 · Words you will meet

Module
A JavaScript file that other files can import from. Our lessons are modules: 04-fusion.js imports lib/fusion.js, which imports three.js.
Dependency
A file your file imports. Together they form a tree: the dependency graph.
Bundle / bundler
A bundler reads the dependency graph and writes one JavaScript file with everything in it. esbuild and Vite are bundlers. esbuild is a command-line program; you run it once and it produces bundle.js.
Minify
Shrink code by removing comments and shortening names. Smaller, unreadable. Bundlers can do it; we do not, so the code in the export stays readable.
Inline / embed
Put a file's contents inside another file instead of linking to it. Inlining a stylesheet means a <style> tag instead of a <link>. Embedding a model means its bytes live inside the HTML.
Base64
A way to write any binary file (a model, an image) using only ordinary letters and digits, so it can sit inside a text file. The cost: about a third bigger.
gzip
Compression, like a zip file. We gzip before base64, which wins the size back (a 14 MB wasm file shrinks a lot).
Blob URL
A temporary address, like blob:null/3f2a…, that points at data held in memory. Anything that wants a file path (a script, a model loader) can be given one.
Import map
A table in the page that says what a bare name like 'three' means: "three": "./vendor/three.module.js".
Wasm
WebAssembly: compiled code the browser runs next to JavaScript. MediaPipe and the depth model ship a .wasm file.

3 · Two ways to make the one file

A · A bundler (esbuild)

The standard way. One command turns the module tree into one script:

npx esbuild 01-anatomy.js --bundle --format=esm --outfile=bundle.js

Add --minify to shrink it. You then still write an HTML file that loads bundle.js, and paste the script into it to get a single file. This is what you will use in real projects, and it needs Node installed.

B · The button in this course (no install)

Every lesson has a ‹› button. In its drawer, ⇩ html builds the single file in your browser with no bundler. It does the same job in five small steps:

1 CrawlStart at the page's script, read each import, fetch that file, repeat.
→
2 EmbedStore every file's text as JSON inside the HTML.
→
3 RewriteReplace each import path with a placeholder.
→
4 LoadOn open, make a blob URL per file, in order, filling in the placeholders.
→
5 RunImport the first one. It pulls in the rest.

You can read all of it: open the drawer on this page and pick Key ideas. The cards "Collect every module", "Rewrite imports to blob URLs" and "Embed big files" are the real code.

7 · When it does not work

The camera does not start
Your browser must allow the camera for the file. Chrome asks the first time; Safari and Firefox can be stricter with files from disk. If so, run the lessons through the server (python3 serve.py).
The file will not email or upload
The big one is 50 MB or more. Share the small one with a server, or use a file-sharing service.
Depth is slow
It uses your graphics card (WebGPU) when the browser has it, and falls back to the processor. Chrome and Edge on a recent computer are best.
The film clips do not play offline
They are streamed from the Mediathèque. The webcam does not need the internet.

The idea to keep

A program is a graph of files. Shipping it means choosing where the files live: next to each other and fetched (a server), packed into one script (a bundler), or packed into the page itself with the heavy files stored as text (embedding). The code does not change; only where it lives.
